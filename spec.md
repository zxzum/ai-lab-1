# Спецификация лабораторной № 2

## Сценарии (наблюдаемый результат)
| Сценарий | Результат |
|---|---|
| «Какая погода в Казани?» | вызов `get_weather(city="Казань")`, ответ с температурой из результата |
| «Москва» (несколько городов) | бот перечисляет варианты, первый не выбирает; «Москва, Айдахо» даёт погоду |
| «Какие пары завтра?» | вызов `get_schedule(date=YYYY-MM-DD)`; пустой день → «занятий нет» |
| «Напомни завтра в 9:00 …» | сообщение с текстом, временем, зоной и кнопками; запись только после «Подтвердить» |
| «Подтвердить» дважды / повтор update | одно напоминание, второй раз «Это действие уже выполнено.» |
| Подтверждение через 5+ минут | «Время подтверждения истекло…», записи нет |
| Напоминание без `/timezone` | просьба сначала задать зону, подготовленного действия нет |
| Вопрос без инструмента | обычный ответ, в `/why`: «ответ без инструмента» |
| Неоднозначный запрос | уточняющий вопрос (`ask_clarification`) |
| MCP-сервер недоступен | `/tools`: «Инструменты сейчас недоступны»; бот отвечает без инструментов |
| Больше 2 MCP-вызовов на сообщение | остановка с сообщением, запись `limit` в аудите |

## Контракты MCP-сервера (stdio)
Все схемы с `additionalProperties: false`; результат в `structuredContent`.
- `get_weather(city: 1..100 симв.)` → `{status: ok|not_found|ambiguous, weather?, candidates[]}`;
  `weather`: место, `temperature_c`, `condition`, `weather_code`, `wind_speed(+unit)`,
  `observed_at`, `timezone`. Open-Meteo (геокодинг + прогноз), 10 с, 1 повтор чтения.
- `get_schedule(date: YYYY-MM-DD)` → `{date, timezone, lessons[{start,end,title,location}]}`.
  Файл — `SCHEDULE_FILE` или `app/mcp_server/data/schedule.json`; путь от модели не принимается.
- `add_reminder(text: 1..500, remind_at: ISO 8601 с поясом, будущее)` →
  `{reminder_id, remind_at, timezone, created}`. Владелец, зона и ключ идемпотентности приходят
  в `_meta.trusted` с HMAC-подписью; секрет бот передаёт серверу при запуске. Без подписи — отказ.
- Ресурс `schedule://current-week` → `{week_start, week_end, timezone, days{дата: [занятия]}}`.

## Состояния подтверждения (`pending_actions.status`)
`pending` → `confirmed` → `executed` | `failed`; из `pending` также `cancelled` (кнопка или
новое действие пользователя) и `expired` (5 минут). Переход `pending → confirmed` атомарный.
Идемпотентность: `UNIQUE (user_id, update_id)` для подготовки и
`UNIQUE (owner_id, idempotency_key)` для напоминаний (ключ = id действия).

## Агентный цикл
Модель получает схемы инструментов (+ `rationale`, + `ask_clarification`). Приложение проверяет имя,
JSON-схему, часовой пояс и время; не больше 2 MCP-вызовов и 4 ходов модели на сообщение.
Инструменты доступны в режиме `/study`; `/translate` и `/code_review` работают как в лабе 1.

## Проверяемые ошибки
сервер не запустился · соединение оборвано · неизвестный инструмент · лишние аргументы ·
тайм-аут/сбой погодного API · неожиданная структура результата · лимит вызовов ·
отмена/просрочка · повтор подтверждения · инструкция в данных инструмента · время в прошлом ·
неоднозначное время при переходе на летнее время · нет часового пояса.

`/timezone` работают; оценка: routing ≥ 10/12, аргументы ≥ 8/9; тег `lab2`.
